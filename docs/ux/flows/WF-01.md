# WF-01 Parent setup and AI connection states

Prompt: [AGENT-PROMPTS.md](../AGENT-PROMPTS.md) §3 (Flow architect), round 3. Builds on round 1 step 4 (`WITHOUT_AI`).

**Trigger:** a new family sets up, or an AI call fails in a way that will keep failing. **Exit:** a working connection (any successful AI call, or the parent saving or reconnecting AI settings), or a parent choosing to carry on without AI.

## Current behaviour (code)

- **Configuration problems:** `aiConnectionProblem` (`src/services.ts`) covers no key, no model, ChatGPT not available here, and ChatGPT needs reconnecting. These show on every screen with the `WITHOUT_AI` statement (round 1).
- **Problems found while working:** a key that is no longer accepted, a used-up plan, an account that is not eligible, or a model that no longer exists. These appear only as a failed job ("Could not finish…" or the ChatGPT messages in `src/jobs.ts`). Afterwards the home and parent screens still claim everything works, so the next try fails again.
- **Photo model:** an unset photo model is used blank (`src/schoolwork.ts`), so reading a photo fails although saving it works.

## Proposed states

| State | Trigger | What still works | Child line (home, mission) | Parent line (banner, overview, controls) | Action | Clears when |
|---|---|---|---|---|---|---|
| `ok` | configured; last call worked | everything | none | none | none | — |
| `missing` | `aiConnectionProblem` (unchanged) | practice with short-answer checks and hints; written answers wait | the round 1 `WITHOUT_AI.child` line | the round 1 `WITHOUT_AI.parent` line | Connect an AI | settings saved |
| `revoked` | 401 or 403 from an API provider; ChatGPT `reconnect` | as for `missing` | "My AI helper can't connect right now. A grown-up can fix it." + the `WITHOUT_AI.child` line | "The AI connection stopped working: the key or sign-in is no longer accepted." + the parent `WITHOUT_AI` line | Reconnect in AI settings | settings saved or reconnected; any later successful call |
| `used_up` | 402, or 429 with a quota or billing reason, from an API provider; ChatGPT `limit` | as for `missing` | "My AI helper is resting for now. You can still practise." + the `WITHOUT_AI.child` line | "The AI plan has used up its allowance for now. AI help pauses for an hour and then tries again, or check the plan." | Check the plan | after 60 minutes the state stops blocking and the next request tries again; a success clears it |
| `not_eligible` | ChatGPT `not_eligible` | as for `missing` | as `revoked` | "This ChatGPT account can't be used for AI help here. Connect another way." | Connect another way | settings saved |
| `model` | 404, or a model-not-found reason | as for `missing` | as `revoked` | "The chosen AI model isn't available any more. Pick another in AI settings." | Choose a model | settings saved; a success |
| `no_photo` | a photo needs reading and no photo model is set (not ChatGPT, whose plan reads photos) | everything except reading photos | photo page: "I can save your photo. To read it, type the page or ask a grown-up to choose a photo model." | controls: "Photo reading is off until you choose a photo model." | Type the page / Choose a photo model | photo model saved |

**Rules**
- A temporary failure (a plain 429 rate limit, a 5xx error, a timeout, or ChatGPT `temporary`) never changes the state. Those jobs say "busy, try again" as today.
- One family has one AI state, stored with the time it was set. No error text and no key material is stored.
- While the state is `revoked`, `used_up`, `not_eligible` or `model`, the round 1 no-AI behaviour applies: written answers are saved for the parent, talk-through is not offered, and topics needing new questions explain why.

**Engine-rule diff:** none.

## Acceptance cases (WF-01-A, round 3)

1. A 401 from the provider sets `revoked`. Child home, parent overview and controls show the revoked wording with Reconnect. A written answer is then saved for the parent, not sent to a failing job.
2. A 429 with `insufficient_quota` sets `used_up`. After 60 minutes the state no longer blocks, and the next successful call clears it.
3. A plain 429 rate limit or a 503 leaves the state unchanged.
4. ChatGPT `limit`, `not_eligible` and `reconnect` map to `used_up`, `not_eligible` and `revoked`.
5. Saving AI settings clears any state.
6. No photo model: the photo page says so before upload, and a typed page still works.
7. No key, error text or provider response is stored with the state.

## Review round 3 corrections

- **ChatGPT 401:** a ChatGPT `reconnect` (401) is not recorded as `revoked`, because the token is refreshed first. Only a failed refresh lasts, and that is stored on the credential (`aiConnectionProblem`).
- **ChatGPT 429:** only a named usage limit (`subscription_sharing_usage_limit_exceeded`) is `used_up`; a plain 429 is a rate limit.
- **Moderation 403:** an API 403 that mentions moderation or flagging is about one message, not the connection.
- **Model text:** model wording counts only on a 400 or 404, never on a 5xx.
- **Database scope:** state writes run in their own database scope.
- **Mission page:** shows the state's child line where talk-through would be.
