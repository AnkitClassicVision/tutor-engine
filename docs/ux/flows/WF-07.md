# WF-07 Parent evidence, plan draft, Apply, Undo

## Current behaviour (code)

- The planner drawer drafts proposals. Talking changes nothing (`test/planner.test.ts:67`; `:52` checks proposal validation).
- Apply (`src/planner.ts` `applyProposal`) runs in a write transaction. A second Apply returns "Already applied" (line 291).
- Undo from the history page (`src/undo.ts`) checks later work with `undoCheck` (`test/undo.test.ts:26`).
- Parent only (`test/journey-http.test.ts:325`).

## Proposed contract

| State | Wording | Action | Effect |
|---|---|---|---|
| `draft` | Proposal card: change, reason, affected dates | Apply / Not now | none |
| `stale` | "Your plan changed since this suggestion. Here is the updated version." | Review again | none until Apply |
| `applied` | "Done. You can undo this from History." | Undo (history) | Versioned decision record |
| `undone` | "Undone. Later work stays saved." | none | New decision; attempts untouched |

**Trigger:** the parent opens the overview or asks the planner for a change. **Exit:** a plan is applied or left unchanged, and the parent returns to the overview.

**Failure and recovery:**
- The AI is unavailable: the planner answers without a model, and Apply still works for drafted changes (`test/planner.test.ts:67`).
- Apply fails part-way: the transaction rolls back, nothing is applied, and the draft stays.
- Apply is sent twice: one effect ("Already applied").
- Undo is blocked by later work: the page explains what stays, and offers a new reviewed plan.
- The drawer closes, or the device locks to student mode: the draft is kept and nothing applies.

**Small proposal:** detect a stale draft. If the class or plan the proposal targets has changed since the proposal was made, refuse Apply with the stale message and offer a fresh draft. Today an outdated proposal is validated against current rules but not against a changed plan.

**Engine-rule diff:** none.

## Acceptance cases (WF-07-A)

1. Closing the drawer leaves no plan change.
2. Applying twice in a row has one effect. Needs an HTTP test.
3. Undo after later answered work keeps that work (`test/pack.test.ts:197`).
4. A student-mode Apply is refused.
5. A stale proposal is refused with the stale message. Needs a test, after the proposal is built.
