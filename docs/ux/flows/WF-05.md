# WF-05 Homework photo, confirm, then help

## Current behaviour (code, 2026-10-19)

1. **Capture:** `/students/:id/materials/new` (`cameraPage`). Photo, or typed transcription. Ages 5–7 get default details (round 1, step 6).
2. **Read:** "Read my pages" (`/materials/:id/extract`) starts an extract job. The model returns questions with `prompt`, `readable` and `confidence` (`material_questions`).
3. **List:** the material page shows each question. A readable one gets "Let's think it through". An unreadable one says "Unresolved. Ask a parent to correct the transcription."
4. **Help:** opening `/questions/:id/help` calls `startGuidance` at once and writes the tutor's opening message. **Nothing asks whether the reading is right.**
5. **Correction:** only a parent can fix the page text (`/materials/:id/correct`, which is not in the student allow-list). That creates a new material revision and re-extracts.
6. **Evidence:** guided attempts are help (`assistance = 1`). Homework sessions count as supported (`supportUsed = "homework"`). A later fresh check is separate evidence.

## Proposed contract

**Trigger:** the child opens a homework question for help. **Exit:** help begins on the confirmed text, or the child leaves with the page saved.

| State | Screen and wording (8–10 and 11–14; ages 5–7 in brackets) | Main action and transitions | Stored effect |
|---|---|---|---|
| `reading` | "Reading your page…" ("Reading your page") | Job runs; page returns to the list | Extract job (unchanged) |
| `to_confirm` | Question card showing the text as read, the page photo, and, when confidence is low, "I might have read this wrong." Heading: "Is this the question?" | **Yes, help me** → `confirmed`. **Fix it** → `fixing`. **Take another photo** → capture (material kept) | None until a choice |
| `fixing` | Text box filled with the reading. "Change anything I got wrong." ("Fix the words.") Hear this for 5–7. | **Use this question** → `confirmed` (child version). **Cancel** → `to_confirm` | Child version saved beside the original reading; the original is never overwritten |
| `unreadable` | "I couldn't read this one." Photo shown. | **Type it** → `fixing` (empty box). **Take another photo** → capture | None. Unreadable is never wrong |
| `confirmed` | Existing help page, using the confirmed text | Help as today | `confirmed_revision` = the material revision; help uses the child version if there is one |
| `parent view` | Material page shows "Checked by [child]" or "Fixed by [child]", with the original reading under "What the photo reading said" | Parent may still correct the page (existing) | A parent correction makes a new revision; earlier confirmations no longer apply to it |

**Rules**
- Tutoring never starts before `confirmed` for the current revision.
- A confirmation belongs to one learner and one revision.
- A repeated "Yes" or "Use this question" has one effect.
- The child's text is the child's words. It is sealed like other child text and is untrusted input to the model, not an instruction.

**Failure and recovery**
- An upload interrupted mid-way is handled by the existing `requestId` de-duplication. A repeated confirmation is safe.
- Camera denied: the file picker or typed transcription (existing).
- A model failure while reading leaves the page saved, with Retry (existing job page).
- If the parent corrects the page after the child confirmed it, the next help opens at `to_confirm` again.

**Engine-rule diff:** none. Homework help stays supported, and confirming does not create evidence.

## Acceptance cases (WF-05-A, synthetic)

1. **Clear question:** the reading is shown, Yes leads to help, and no tutor message exists before Yes.
2. **Ambiguous fraction:** a low-confidence reading shows the warning. The child fixes "1/2" to "1/3"; help receives "1/3", and the original "1/2" is still stored and shown to the parent.
3. **Several questions on a page:** each needs its own confirmation; confirming question 1 does not confirm question 2.
4. **Unreadable:** the child types the question and help starts; nothing is graded as wrong.
5. **Repeated Yes:** two posts make one confirmation and one opening message.
6. **Parent correction after confirmation:** help asks to confirm again for the new revision.
7. **Sibling:** a confirmation by one child does not apply to another child's material (ownership is checked).
8. **Camera reversed:** denial then a late allow keeps the form (existing `devices.spec.ts:50`).
9. **Interrupted upload:** a retry makes one record (existing `recovery.spec.ts:43`).
10. **Age 5–7:** the confirm screen has Hear this and one main button, with 64 px targets.

**Storage, for M5:**
- `material_questions.confirmed_revision INTEGER`
- `material_questions.child_prompt TEXT` (sealed)
- `material_questions.confirmed_by TEXT` (student id)
