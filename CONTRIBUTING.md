# Contributing

Thank you for helping. Teachers, parents, designers and developers are all useful here.

## Ground rules

- **No real children's data, ever.** Not in issues, pull requests, fixtures or screenshots. Use clearly synthetic names ("Synthetic learner") and made-up work. The review pack's images say "SYNTHETIC REVIEW FIXTURE" on purpose.
- **Evidence stays honest.** Help, hints and guided steps never count as mastery. Changes to scoring, mastery or scheduling need a test that shows the rule. See [docs/tdd/](docs/tdd).
- **Children first in the UI.** Every child screen must work by touch and keyboard on phone, tablet and laptop, for ages 5–7 (read-aloud, large targets) up to 14. The browser suite runs an accessibility audit.
- **The parent decides.** The AI proposes and the parent applies. Don't let a model change a child's plan on its own.

## Getting started

```bash
npm ci
npm start                 # http://127.0.0.1:8787
npm run typecheck
npm test
npx playwright install --with-deps && npm run test:browser
```

CI runs the type check and the unit and browser suites on every pull request. Keep them green, and add tests with your change.

## Where help is most welcome

- **Teaching quality.** Mission design, explanations for ages 5–7, better diagnosis of errors. The rules live in `src/engine/`; the AI's instructions live in `skills/`.
- **Curriculum.** The built-in math backbone (`src/data/math-backbone.json`) has 32 concepts. A fuller, openly licensed concept graph for math, and starter graphs for reading and science, would help every family.
- **AI quality.** Review the synthetic cases in `eval/review-pack/` and add cases. See [docs/MODEL-EVALUATION.md](docs/MODEL-EVALUATION.md).
- **Child safety.** Better checks on what AI output reaches a child, and defences against instructions hidden in homework photos.
- **Worlds.** New visual worlds are generated by `scripts/build-worlds-css.py`. See [DESIGN.md](DESIGN.md).
- **Translations, accessibility, self-hosting guides.**

## Style

Match the surrounding code: TypeScript run directly by Node (`--experimental-strip-types`), server-rendered HTML, small progressive-enhancement scripts, no client framework. Database changes need a migration in `src/migrations/` (Postgres) and the matching SQLite change in `src/journey-db.ts`. Text a child sees should be short, concrete and kind.
